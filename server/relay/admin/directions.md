# lolPing 中继后台 · 三方向

## Spec（三版共同输入）

| 项 | 内容 |
|---|---|
| 是什么 | 自建 Nostr 中继的运维后台，看谁在用、管住谁 |
| 受众 | 只有一个人：服务器主人。手机和桌面都会看 |
| 场景 | 想确认「现在有没有人在用」「刚才那个 IP 是谁」「要不要封掉」 |
| 核心信息 | ① 在线数 ② 房间数 ③ 谁在线（IP/时长/流量） ④ 24h 趋势 ⑤ 封禁操作 |
| 情感基调 | 可靠、不喧哗。这是自己看的东西，不是给别人演示的 |
| 输出格式 | 1440×900 桌面为主，375 宽可用；单页 HTML，无框架 |
| 数据来源 | `GET /api/overview|sessions|rooms|timeseries|history|bans`，5 秒轮询 |
| 约束 | 后端只监听 127.0.0.1，走 SSH 隧道访问；不编造数据 |

## 我加的功能（不在用户原始要求里）

1. **单 IP 多连接标记** —— 同一 IP 开了 >1 条连接时高亮，这是刷子或重连风暴的第一信号
2. **事件速率** —— 每分钟事件数，异常突增一眼能看到
3. **房间热度** —— 按事件数排序，看哪个房间在跑
4. **一键封禁（1h / 24h / 永久）** —— 带原因输入，直接踢下线
5. **历史会话** —— 关掉的连接也留档，事后能查「刚才那个是谁」

---

## 方向 A · 控制室

- **逻辑与来源**：NOC / 广播控制室。参考真实运维大屏（Grafana 的深色默认、Cloudflare 的实时面板）——大数字、等宽字、状态灯、密集表格。
- **借的是什么**：单色深底 + 一条信号色；数字用等宽字体撑起层级，标签用极小号大写；表格行高压缩到 32px，信息密度优先；状态用「灯 + 文字」而不是纯颜色。

## 方向 B · 账本

- **逻辑与来源**：报刊数据版 / 会计账簿。参考 FT、NYT 的数据专题页——衬线大标题、细线分隔、大留白、无卡片无阴影。
- **借的是什么**：12 栏网格压成单栏正文宽度（1080px）；标题衬线、正文无衬线、数字用旧式数字（`font-variant-numeric`）；用「一句话结论 + 数据表」的叙事顺序，先给判断再给明细；颜色只用在数字的正负和封禁按钮上。

## 方向 C · 拓扑

- **逻辑与来源**：网络拓扑图 / 电路板。参考 Observable 的网络图、BGP 可视化——空间即信息，节点位置本身就是数据。
- **借的是什么**：房间作为中心节点，客户端作为卫星节点环绕，连线粗细表示事件量；右侧窄栏放详情，选中节点才展开；几乎无边框，靠暗场和单色高亮建立层级。
