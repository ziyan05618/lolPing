> **实施备注（2026-11-03）**：需求 C 的私聊方案在实现时被推翻，改用每会话 X25519 协商（提交 `2fec66e`）。

| # | 需求 | 类型 |
|---|---|---|
| A | 房主退出房间后，房主身份应转给房内其他人；而不是原房主回来还是房主 | 行为修正 |

## 2. 三个必须先知道的约束

**2.1 私聊不能用「广播 + 客户端过滤」。**
同房间所有成员共用同一把房间密钥（由房间码派生），任何广播出去的包**所有人都能解密**。想只让一个人看见，必须走**只有双方订阅的派生 topic**，不能靠接收端自觉。

**2.2 中继对每个连接的订阅数有上限，现在是 8。**
`server/relay/lolping-relay.py:42` `MAX_SUBS_PER_CLIENT = 8`。私聊要为每个其他成员各开一个 topic，16 人房就是 15 个订阅 + 1 个房间订阅。**必须把这个上限提高**（建议 64），否则人一多私聊直接失效。

**2.3 中继不知道「谁在房间里」。**
HTTP 接口是无状态的，请求都从 nginx（127.0.0.1）过来，无法区分调用者。所以「谁还在房里」只能靠客户端**主动心跳**，不能靠连接状态推断。

## 3. 需求 A · 房主转移

### 3.1 现状与问题

`room_owner` 表记录 `topic → owner_token`，先到先得，永不改变。原房主退出后 token 仍归他，重进还是房主。
`docs/room-policy-spec.md` 第 7.2 条把这个写成了预期行为——**现在要改**。

### 3.2 新模型：成员令牌 + 心跳 + 顺位继承

把「房主令牌」升级为「成员令牌」：

- 客户端首次启动生成 **一个** `memberToken`（32 hex），存 `settings.json`，**不随房间变化**
- 进房后每 **15 秒** 心跳一次：`POST /policy/heartbeat {topic, member_token}`
- 中继维护 `room_member(topic, member_token, joined_at, last_seen)`
- 房主 = `room_owner.topic` 指向的那个 `member_token`

**转移规则**（每次心跳时判定）：

1. 房主的心跳超过 **45 秒**没来 → 视为离开
2. 从该房间 `last_seen` 在 45 秒内的成员里，选 `joined_at` 最早的那个，改成新房主
3. 房间内没有活跃成员 → 清除房主，下一个进房的人认领

**主动释放**：客户端退房时立即 `POST /policy/leave {topic, member_token}`，中继立刻按上面第 2 条转移，不用等 45 秒。

### 3.3 心跳响应

```json
{"owner": true, "limits": {"emote_per_minute": 20, "ping_per_second": 5, "text_per_minute": 10}}
```

客户端据此知道**自己现在是不是房主**——转移发生时，新房主在下一次心跳（≤15 秒）就会拿到 `owner: true`，设置页自动从只读变成可编辑。

### 3.4 兼容

`ownerTokens` 字段废弃，改为 `memberToken: string`。
老设置文件没有 `memberToken` → 首次启动生成并写入。旧的 `ownerTokens` 直接丢弃（房间会被重新认领，可接受）。

## 4. 需求 B · 冷却提示

### 4.1 触发点

`src/main/roomManager.ts` 的 `allowPolicy()` 返回 `false` 时。它已经算出了窗口内最早的发送时间，补一个返回值：

```ts
// 返回被拒绝时的剩余冷却毫秒，放行时返回 0
{ allowed: false, retryAfterMs: window - (now - times[0]) }
```

### 4.2 只有发送者看得到

配额检查在**发布前**和**渲染前**各跑一次。只有「自己发的被自己拦下」才提示；别人被拦，观看者什么都不显示（否则满屏都是别人的冷却提示）。

判断依据：被拦的消息的 `pubkey` 是不是本机自己的。

### 4.3 UI

在主进程 emit 一个新事件：

```ts
'policyCooldown' → { type: 'emote' | 'ping' | 'text', retryAfterMs: number }
```

渲染层在轮盘中心显示一行小字：`表情冷却 12s`，每秒递减，到 0 自动消失。

**不要**用系统通知、不要弹窗、不要响——它只是个轻提示。

### 4.4 文案

i18n 加三条（中英各一）：
- `cooldown.emote` = `表情冷却 {n}s`
- `cooldown.ping` = `发送过快，{n}s 后重试`
- `cooldown.text` = `文字冷却 {n}s`

## 5. 需求 C · 私聊表情

### 5.1 私聊通道

对房间内每两个成员 (A, B)，派生一个独立 topic：

```
whisperTopic = HMAC-SHA256(roomKey, "whisper:" + min(peerA,peerB) + ":" + max(peerA,peerB))[:32] → hex
```

- `roomKey` 就是现有房间密钥（`roomCrypto.ts` 里已有的那个）
- `peerA/peerB` 是成员在房间里的 **peer id**（不是 pubkey）
- 双方算出同一个值，中继看到的是又一个不透明 topic

**订阅时机**：进房拿到成员列表后，为每个其他成员订阅其 whisper topic；成员进出时增删订阅。退房时全部取消。

**注意 2.2**：把 `MAX_SUBS_PER_CLIENT` 提到 64，并在客户端做保护——成员超过 20 人时私聊功能关闭（提示「房间人数过多，私聊不可用」）。

### 5.2 消息格式

私聊表情复用现有的 `emote` 消息，加一个字段：

```ts
{ t: 'emote', e: 'GG', fx: ..., shared, to: '<peerId>' }
```

- 发送：**只发到** `whisperTopic(A,B)`，不发房间 topic
- 接收：从 whisper topic 收到的消息，按 `to` 校验等于自己的 peer id，否则丢弃
- 房间 topic 上收到的、带 `to` 字段的消息 **一律丢弃**（防止有人往房间 topic 上发私聊包钓鱼）

### 5.3 配额怎么算

私聊表情**仍然计入发送者的表情配额**——否则私聊就成了绕过限流的后门。计数键不变（按 pubkey + type），与是否私聊无关。

### 5.4 交互

**内环选人**（现有轮盘中心那块 `EMOTE` 区域，见用户截图）：

- 内环按房间成员数等分扇区，每格显示成员名
- 悬停某格 → 该格高亮，中心显示该成员名字
- 点击某格 → 进入「私聊模式」，中心显示 `私聊 · <名字>`，外环表情全部改为发给这个人

**波浪键锁定**：

- 悬停在某个成员名字上时按 `~`（VK_OEM_3，Tab 上面那个键）→ 锁定该成员
- 再按一次同一个人的 `~` → 解锁
- 锁定状态下悬停**另一个人**并按 `~` → 切换目标
- 锁定后关闭轮盘，之后按表情键发出去的**全部是私聊**，只发给他

**视觉**：

- 锁定中：中心常驻 `🔒 <名字>`，外环边框换成私聊配色（建议用琥珀色，与现有的信号绿区分）
- 私聊表情在接收方屏幕上**只出现在目标那里**，别人完全看不到

### 5.5 锁定状态的存放位置

放渲染层的会话状态，**不写 settings.json**——退出房间、换房间一律清除。锁定的成员离开房间也要自动解除。

## 6. 接口变更汇总

| 方法 | 路径 | 变更 |
|---|---|---|
| POST | `/policy/heartbeat` | 新增。`{topic, member_token}` → `{owner, limits}` |
| POST | `/policy/leave` | 新增。`{topic, member_token}` → `{ok}` |
| POST | `/policy/claim` | 保留，语义改为「首次进房注册成员」 |
| POST | `/policy/policy` | 保留。鉴权从 `owner_token` 改为「调用者的 member_token == 当前房主」 |
| GET | `/policy/policy/<topic>` | 保留，公开只读 |

nginx 的正则要同步放行 `/policy/heartbeat` 和 `/policy/leave`。

## 7. 边界情况

1. **两人同时心跳，房主刚超时**：只有先到的那次触发转移，后到的看到已是别人，不重复转
2. **原房主 44 秒后回来**：45 秒内仍算在房，不转移；超过就转走了，他回来是普通成员
3. **新房主 15 秒内没发现自己成了房主**：设置页仍显示只读，下次心跳刷新。可接受
4. **私聊对象退房**：本地订阅取消，锁定自动解除，提示「对方已离开」
5. **房间满 20 人**：私聊关闭，内环显示「人数过多」
6. **自己给自己私聊**：内环不显示自己，禁止
7. **旧客户端（0.6.2）**：不认识 `to` 字段，会当普通表情显示——**这是隐私漏洞**。所以私聊包只发到 whisper topic，旧客户端根本没订阅那个 topic，收不到。**不要**往房间 topic 发任何带 `to` 的包
8. **中继重启**：`room_member` 落库，重启后 45 秒内的心跳仍有效

## 8. 验收标准

**A · 房主转移**
- [ ] 你建房 → 朋友进房 → 你退房 → **45 秒内**朋友变成房主（设置页从只读变成可编辑）
- [ ] 你重新进房 → **你是普通成员**，看不到编辑框
- [ ] 房间只剩你一个人 → 你是房主
- [ ] 所有人退房后重新建房，第一个进的人是房主

**B · 冷却提示**
- [ ] 配额设 5，自己连发 6 个表情 → 第 6 个不出现，中心显示 `表情冷却 Ns` 并递减
- [ ] 冷却结束后能正常发
- [ ] 别人被限流时，**你屏幕上不出现任何提示**

**C · 私聊表情**
- [ ] 内环显示房间成员（不含自己）
- [ ] 点击某人 → 中心显示 `私聊 · 名字`，发的表情只有他和你看得见
- [ ] 第三个成员**完全看不到**这条私聊表情（不是变灰、不是延迟，是根本没有）
- [ ] 悬停名字按 `~` 锁定，关轮盘后直接按表情键 → 仍是私聊
- [ ] 同一人再按 `~` → 解锁，恢复全房间广播
- [ ] 换一个人按 `~` → 目标切换
- [ ] 锁定对象退房 → 自动解锁并提示

**回归**
- [ ] `npm run typecheck`、`npm test`、`npm run test:helper`、`python -m unittest discover -s server/relay -p "test_*.py"` 全绿
- [ ] 房间人数 3 人时，普通表情仍然三人可见（私聊不能污染公共通道）
- [ ] 中继 `ws` 握手仍 101，能力路径仍生效

## 9. 不要做的事

- **不要**用「房间 topic 广播 + `to` 字段过滤」实现私聊——同房同密钥，人人都能解密
- **不要**让私聊表情绕过配额计数
- **不要**把 `memberToken` 写进日志、API 响应或房间消息
- **不要**改 `PROTOCOL_VERSION`（`to` 字段对旧客户端是未知字段，安全）
- **不要**删公共中继
- **不要**把锁定状态持久化到 settings（换房必须清除）
- **不要**在房主转移上用「连接断开」判定——中继分不清谁是谁，必须靠心跳
